How It Works

Nothing is fetched while you wait.

The corpus is built in the background. A request only ever reads what is already on disk, so a slow platform is a background problem, never yours.

01
Capture
A signed-in browser reads public posts. RedNote and Google Maps, on a schedule.
02
Extract
Venue, dish, sentiment and the writer's own excerpt, parsed into one schema.
03
Corpus
Normalised, deduplicated, geocoded. Postgres, not a cache of somebody else's API.
04
Rank
Craving, company, distance and the hour of the day, scored locally.
05
Cite
Every result carries the post it came from, or it is not returned at all.
No single source is load-bearing
Any platform can go dark mid-sprint. Two sources mean the app degrades instead of dying.
A pick with no post is not a pick
An entry that cannot be cited is dropped before the response is built, never returned with a caveat.
